# CODEMAP

Durable map of the Zəka (AzTU Rəqəmsal Kampus) code base: what exists, how real it is, where it lives, and what will hurt you.

## 1. How to use this map

1. Find the area in section 2 (what exists and how mature it is), then check section 6 (landmines) for the same files before changing them.
2. Every `path:line` is repository-relative and valid for commit `24fae45` (branch `claude/tender-meitner-avsvvh`); re-locate by symbol name after later commits.
3. Before planning a university feature, read section 5: it says which capabilities are absent, seeded-only, partial or implemented.

## 2. Module map

Request path: `run.py` -> `app/web.py` (`make_server`, `Router`) -> `app/common.py` (`before`: session + role gate; `after`: commit/rollback) -> handler in `app/r_*.py` -> `app/store.py` helpers / raw SQL -> dict response localised by `app/i18n.py`. Route modules are imported in a fixed order by app/routes.py:2; **[HEAD]** 115 routes: core 16, learning 36, services 15, news 9, academy 11, admin 6, support 14, radar 8.

### 2.1 Core platform (`run.py`, `app/web.py`, `app/common.py`, `app/routes.py`, `app/api.py`, `app/store.py`, `app/i18n.py`, `tools/i18n.py`)

The whole platform layer. `run.py` starts a stdlib `ThreadingHTTPServer`; `app/web.py` is a hand-written HTTP layer (regex router, Request/Response, static files, security headers, JSON localisation); `app/common.py` holds the per-request lifecycle (SQLite connection, session lookup by cookie or `X-Session` header, role gate, commit/rollback) and shared helpers (one-time view keys, course access, AI quota, chat storage, citations); `app/store.py` holds the entire schema (**[HEAD]** 42 tables, 7 indexes, no foreign keys, `SCHEMA_VERSION = 4` at app/store.py:735), the storage helpers (settings, audit, notify, files, materials, documents) and `seed()`, which fabricates every academic record; `app/i18n.py` is the runtime translator and `tools/i18n.py` the dev toolchain. The HTTP, i18n, file, material-index and document-numbering code is real logic. The academic core is not: users, groups, courses, enrolments, timetable, lessons, attendance, grades, request types, campus KB, academy content and tools are INSERTed only inside `seed()`, past-semester transcript scores come from a PRNG, and identity is five passwordless demo personas.

### 2.2 Learning (`app/r_learning.py`, `app/engine.py`, `app/tutor.py`, `app/refs.py`)

The whole learning backend: the routes in `r_learning.py` (courses, materials, schedule, attendance, grades, AI tutor, campus assistant, quizzes, teacher inbox, Test studio; **[HEAD]** 36 `@R` routes), the offline AI engine in `engine.py` (Azerbaijani tokeniser/stemmer, in-memory BM25, text extraction from md/txt/docx/pptx, regex PII masking, rule-based question generation and grading, optional LLM HTTP client), the answer composer in `tutor.py` (Socratic/explain/practice/campus text, LLM prompt) and `refs.py` (static, https-only reference lists from `content/references.json`). Real, working server logic: material upload -> chunk -> index, grounded tutor and campus answers with citations, question drafting/approval, quiz creation, attempt auto-grading, result analytics, ask-the-teacher inbox, tutor settings and insights. Demo-only: every academic master record. `courses`, `enrollments`, `timetable`, `lessons`, `attendance` and `grades` are INSERTed only by `store.seed()`; this slice exposes only GET views over them, lessons stop at the seed day, the past-semester transcript and GPA are random numbers, and "graded" quizzes never reach the gradebook although the UI says they do. The "AI" is rule-based by default: the LLM is wired only into tutor Socratic/explain mode; campus assistant, practice mode and Test studio never call it, and generation only works on materials written in the demo's "Term — definition" Azerbaijani engineering style. `app/tutor.py` and `app/refs.py` are identical on `main` and `24fae45`.

### 2.3 Portal shell, e-services and documents (`app/r_core.py`, `app/r_services.py`, `app/docs.py`, `app/qr.py`, `app/pdftext.py`)

The portal's identity/shell API (`r_core`: passwordless demo login, profile, prefs, notifications, badges, guide, global search, file upload/view/preview) plus the whole e-services subsystem (`r_services`: 13 seeded request types rendered from a JSON field schema, server-side validation, student submit/resubmit/cancel, office return/reject/approve/issue, message thread, SLA, office KPIs, document registry, revoke, public `/verify`). `docs.py` renders issued documents and the verification page as server-side HTML with an inline SVG QR from `qr.py` (own encoder, versions 1-10, ECC M; the reader round-tripped all 213 payload lengths through zxing-cpp); `pdftext.py` is a regex-based PDF text extractor used only for the attachment preview. The request state machine, validation, attachments, notifications and registry are real working logic, but everything they stand on is demo data: one fixed user per role with no credentials, one faculty/specialty for the whole database, request types that exist only in `content/seed.json` with no admin editor, transcript grades that are random numbers, attendance that only the seed ever creates, and documents that carry a hard-coded "DEMO - no legal force" footer, no signature, and a "SHA-256 check mark" that is printed without ever recomputing the hash. Of the 13 services only 3 produce a document and only 1 (absence excuse) changes any other system record. Multi-step approval is cosmetic: every step is performed by the same office/admin role and the API lets `issue` skip all steps.

## 4. Extension points

**Add a route**
- Create `app/r_<module>.py`, declare handlers with `@R("METHOD", "/api/x/{id:int}", roles=(...), auth=True)` (`R` is the shared `Router` instance, app/common.py:15; decorator and matching in app/web.py:198-210), and add the module to the import list in app/routes.py:2. Import order is match order and the first matching pattern wins (app/web.py:~212-224); `{id:int}` compiles to `[0-9]+` and `{x}` to `[^/]+` (app/web.py:202-204), which is why `/api/news/manage` (app/r_news.py:129) coexists with `/api/news/{id:int}` (app/r_news.py:66). Return a dict/list for JSON, or `web.Response` / `html_resp` / `redirect` for anything else.
- **[HEAD]** read the body through the typed accessors (`req.json().text/integer/number/array/ids/obj`, `req.qint`) so a wrongly typed value is a 400 (app/web.py:73-127, 174-176); add a `RateLimiter` entry to `LIMITS` for expensive or public endpoints (app/security.py:85-93).
- The decorator checks only the role. Every handler that takes an id needs its own ownership helper; copy `course_access(req, cid)` (app/common.py:106-115, lets office/leader/admin into every course), `_req_for` (app/r_services.py:222), `file_access` (app/r_core.py:271), `_doc_allowed` (app/r_services.py:469), `_ticket_for` (app/r_support.py:34-38; answers 404 to non-owners) or `_get` (app/r_news.py:37-41, audience + draft check).
- Role groups: `STAFF = (office, admin, leader)` (app/common.py:19); `r_support` defines module-local `DESK = (office, admin)` and `INSIGHT = (office, admin, leader)` (app/r_support.py:14-15). A new staff role (department head, dean) must be added to each of these tuples and to `audience_for` (app/r_news.py:16-17).
- Request lifecycle: `before()`/`after()` (app/common.py:~43-64) are the single place where identity is resolved and the transaction is closed. Real login/SSO, tenant resolution and per-request audit belong there; the `users`/`sessions` tables (app/store.py:25-28) need new columns first.

**Add a page (frontend)**
- Anything under `static/` is served automatically (app/web.py:272-273, 314-322). **[HEAD]** the SPA has no build step: `static/index.html` loads `static/js/main.js` as one ES module (static/index.html:20), which imports the page modules (static/js/main.js:6-16); a page is registered with `route("/path/:param", async (el, p, q) => ...)` from `static/js/core.js` (static/js/core.js:51-63) and added to the role menu in `NAV` (static/js/shell.js:16). This paragraph is the map writer's own reading; no reader pass described the frontend structure.
- A new nav badge needs a key in `r_core.badges` (app/r_core.py:~124-147) and its consumer in `static/js/shell.js`. A new notification kind needs an icon in `N_ICON` (static/js/shell.js:~52-53). A new audit action code needs a label in `ACTIONS` (static/js/staff.js:134-146), otherwise the raw code is shown.
- The CSP (app/web.py:~227-236) allows only same-origin scripts, styles, images (plus `data:`) and XHR, so an external SSO widget, CDN, map or analytics script requires editing that header.
- To open a file or page in a new tab without a cookie, issue `common.make_key(kind, id, user_id)` and extend the hard-coded prefix list and kind mapping (app/common.py:49, 79), which today know only `/doc/`, `/api/files/` and `/syllabus/`.

**Add a table or change the schema**
- Append `CREATE TABLE IF NOT EXISTS` to `SCHEMA` (app/store.py:~22-101). A brand-new table is created on the next start without touching `SCHEMA_VERSION` (`executescript` at app/store.py:753); a changed column in an existing table is never applied, and bumping `SCHEMA_VERSION` (app/store.py:735) deletes the database. A migration runner has to replace the version check (app/store.py:~740-751) before any real data exists.
- `seed()` (app/store.py:~389-732) is the only writer of users, groups, courses, enrolments, timetable, lessons, attendance, grades, request types, KB, academy and tools. A new module that needs master data must add CRUD endpoints or an import path, and `init()` must gain a no-demo mode (app/store.py:754-755 always seeds an empty database).
- Settings: `store.setting(c, key, default)` / `store.set_setting(c, key, value)` (app/store.py:161-167) give a JSON key/value store; expose a new key through an admin endpoint modelled on app/r_admin.py:~104-118.

**Add a translated string**
- Wrap server strings with `S`/`T3`/`E`/`S_` (app/i18n.py:74-86), run `tools/i18n.py extract`, translate into `i18n/en|ru/*.json`, run `build` and restart (catalogs load at import, app/i18n.py:199). Response dict strings use `T3(...)` (app/r_learning.py:~356, 390, 773); vocabulary constants are marked with `S_()` (app/r_learning.py:39; app/tutor.py:172-173); text placed under a key in `SKIP_KEYS` (for example chat `content`) must be localised at compose time with `S(text, lang)` (app/tutor.py:26; app/i18n.py:172).
- A new non-`r_` Python module must be added to the implicit-scan list (tools/i18n.py:276), a new content JSON to `content_strings()` (tools/i18n.py:301-368), new canonical vocabulary to `VOCAB` (app/i18n.py:195-197), and any response key that carries user-written text to `SKIP_KEYS` (app/i18n.py:172), or the handler must set `req.raw_i18n`.
- Option values stay canonical Azerbaijani and are mapped back with `i18n.canon`; changing an Azerbaijani option label breaks the phrase maps in app/docs.py:14-20, 96-102 and the language switch at app/docs.py:148. The Azerbaijani source string is the catalog key: editing it drops its translations.
- **[HEAD]** frontend strings use `t("...", params)` from `static/js/i18n.js` (static/js/i18n.js:49).

**Add a notification**
- `store.notify(c, user_ids, kind, title, body, link)` takes one user id or a list, `T3(...)` dicts for title/body and an SPA hash path as link (app/store.py:175-179; **[HEAD]** signature at app/store.py:175); examples at app/r_learning.py:390, 638, 773. There is no outbound channel: e-mail, SMS or push would be added inside this one function.

**Add an audit entry**

## 6. Landmines

Merged from the core, learning and services/documents reader passes (made on `main`) and de-duplicated; the academy/admin/support/news reader's landmine list did not reach this map. Each item ends with its state on `24fae45`: **open** (re-checked in code, or confirmed by the inventory row named), **changed** (partly addressed by the merge), **fixed**, or **not re-checked** (true on `main`; verify before relying on it).

### Identity, access and privacy

- **L1. The whole database can be erased without a personal credential.** The demo login (`POST /api/auth/demo {"role":"admin"}` or `GET /demo/login?role=admin`) returns an admin session, and `POST /api/admin/reset` calls `store.reseed()`, which runs `DELETE FROM` on every table and re-seeds demo data (verified on a scratch DB on `main`). app/store.py:~772-780; app/r_admin.py:141-146; app/r_core.py:~63-71. **changed**: a shared access code gates a new visitor and is mandatory for a non-loopback host unless `ZEKA_ALLOW_OPEN_DEMO=1` (run.py:50-54; app/r_core.py:17-30), but anyone who knows that one code can still become admin and reset (app/r_admin.py:141-146).
- **L2. No real identity.** `users` has no credential, e-mail or external-id columns (app/store.py:25-27); the only login maps a role to one fixed seeded user, over POST and over a plain GET link (login CSRF; every "student" session is the same person); one role per user (single TEXT column). app/r_core.py:~30-45, ~63-71. **open** (inventory row 1); on `24fae45` a `user` parameter also signs in as any student username (app/r_core.py:34-37) and logins are rate-limited (app/security.py:86-87).
- **L3. Session id leaks past HttpOnly.** It is returned in the login JSON and accepted from an `X-Session` header; the frontend keeps it in `sessionStorage`, so any XSS can steal it. app/r_core.py:67; app/common.py:26-27; static/js/main.js:78. **open** (app/r_core.py:67; app/common.py:26-27).
- **L4. Sessions never expired, were not rotated and never purged; the cookie had no Max-Age and gets `Secure` only when `--public-url` is https.** app/store.py:28; app/common.py:~35-40, ~43-54; app/r_core.py:43, 78. **fixed** for lifetime: absolute lifetime `ZEKA_SESSION_HOURS` (default 12) with `Max-Age`, purge at the next login, and a role switch ends the previous session (app/common.py:30-40, 47-48; app/r_core.py:38-41). `Secure` still depends on the public URL.
- **L5. No faculty/department or ownership scope for staff.** Every office/admin/leader user sees every request of the whole university, including health reasons and social-scholarship categories (orphan, disability, martyr family); every office/admin user can open any file of any user (also files never attached to a request and support-ticket attachments); `course_access` lets every office/leader/admin user read any course, material, tutor-history endpoint and chunk. app/r_services.py:222-226, 234-246; app/r_core.py:271-278; app/common.py:106-115; app/r_learning.py:138-139. Probe on `main`: a leader read a health request (200). **open** (app/r_services.py:224-228; app/r_core.py:271-278; app/common.py:106-115).
- **L6. Request thread has no role or state guard.** A leader can post into any student's request thread and it reaches the student titled "Dekanlıqdan yeni mesaj"; messages can be posted on closed requests; there is no duplicate-request or rate check on submission. app/r_services.py:~259-273, ~292-305. **open** (app/r_services.py:292-305).
- **L7. Reads of personal data are not audited although the UI says "Hər baxış audit jurnalına yazılır".** Opening a request or a document writes no audit row (only file view/preview do). app/r_services.py:276-289, 483-497 vs app/r_core.py:294, 322; static/js/services.js:298. **open** (inventory row 29).
- **L8. Consent is recorded but never enforced server-side.** app/r_core.py:~82-90. **changed**: on `main` arbitrary client JSON of any size was copied into the audit detail; on `24fae45` only the `{ai, external}` choice is stored and audited, and `external` gates the LLM path (app/r_core.py:82-90); the basic AI consent is still not checked by the tutor and cannot be withdrawn (inventory row 30).

- **L11.
